# 产品定位重定向讨论：从"非技术用户的 AI 建站工具"到"新手开发者的玩具工厂"

> 这是一份讨论稿，邀请大家参与定位讨论后再更新文档与 README。

## 一、背景与动机

当前定位（非技术用户 + 自带 API Key）存在两个结构性问题：

1. **用户面过窄**：目标用户必须同时满足"愿意购买 API Token"和"不是开发者"。这两个条件叠加后市场非常狭小——愿意为 AI 付费且懂 API 的人，绝大多数恰恰是开发者。
2. **产出无归处**：非技术用户生成的 App 无法上架（需要开发者账号、实名、软著），没有原生能力、没有云服务，只能侧载。用户做完之后"没有地方用"，这个落差会直接反噬口碑。

## 二、重定向目标用户：新手开发者（学生群体）

核心洞察：新手开发者（学生、转行者）有真实且未被满足的需求——**想自己写个玩具**。

拆解"玩玩具的欲望"：

| 欲望成分 | 产品语言 |
| --- | --- |
| 创造欲 | 从 0 到 1 做出"属于我的东西"，哪怕很蠢 |
| 即时满足 | 改 → 立刻看到效果（预览刷新是玩具的心脏） |
| 分享欲 | "看，我做的"——APK 发到同学手机上 |
| 掌控感 | "是我的 idea 变成现实" |

为什么这个群体适合：

- **环境是新手最大拦路虎**：Android Studio / Node 配置劝退无数人；手机免环境开发正好击穿它
- **API Key 门槛变成课程而非障碍**：学生本来就要学 API Key 是什么；国产模型（DeepSeek/Qwen/GLM）便宜到几块钱能用很久
- **规模巨大、零获客成本**：每年几百万学前端/移动开发的学生与转行者；社团、学校、B 站教程自然传播
- **协会自举（dogfooding）**：协会教成员写前端，就用自己做的工具——项目本身就是协会的教具，招新演示、内部教学、示例产出全用它

## 三、产品形态：聊天式 AI 渐进构建

- **创意归用户，构建归 AI**：用户只提供 idea（聊天形式），AI 是构建主体
- **渐进式构建，不是一键生成**：随对话慢慢生长——idea 是种子、对话是浇水、预览是生长、APK 是开花
- **构建过程 = 游戏过程**：每轮对话都有新变化，这是与 Bolt 式一键生成的核心区别，也是"玩玩具"体验的来源

## 四、对当前 MVP 文档的影响

- **技术栈不变**：静态 HTML/CSS/JS + Kotlin Local Server + 预编译壳 APK——对"玩具"完全够用，无需 Node/React/Vite
- **Agent 行为需要设计**（MVP 文档未覆盖）：
  - idea 追问：把用户模糊的想法玩具体（"它吃什么？画风可爱还是酷？"）
  - 阶段感：骨架 → 功能 → 装饰 → 打磨，每阶段让用户看预览做决定
  - 节奏控制：宁可留白邀请用户参与，不要一口气做完
- **建议新增：无 Key 演示模式**：内置教学示例项目（带注释），没有 Key 也能玩，填 Key 解锁生成——注册门槛变成教程第一步

## 五、待讨论

1. 无 Key 演示模式的形态与内置示例规模
2. 示例模板库方向（玩具店心态：电子宠物、音乐可视化、小游戏、抽卡……）
3. "玩"与"学"的平衡：AI 解释机制（"这次改了什么、为什么"）要不要、多深
4. 是否调整 README / 项目叙事

## 六、结论草案

> 一个让你在手机上聊着天，看着自己的 idea 一点点长成 App 的玩具工厂——AI 是构建主体，用户只负责说，预览负责展示过程，APK 负责炫耀。
